## Гипотеза

Обучаемая общая матрица испытуемого может улучшить перенос LISA на новых людей
относительно арифметического среднего индивидуальных матриц обучающих людей.
Эффект нужно проверить при одинаковых данных, разбиениях, сидах, настройках
обучения и галерее аудиокандидатов. Это гипотеза, а не установленный результат.

Повторное выполнение предобработки обеспечивает контроль происхождения данных,
но само по себе не доказывает отсутствие утечек. Это проверяется отдельно по
правилам доступа к данным, разбиениям и выбору модели.

## Задачи

1. Подготовить собственный комплект данных по авторскому clean-пайплайну:
   RAW MEG-MASC, предоставленные ICA-решения, MFA, аудиопризнаки, MEG и CSV.
2. Проверить соответствие файлов, временную синхронизацию и целостность разбиений.
3. Зафиксировать единый протокол до запуска сравнений и просмотра новых test-метрик.
4. Заново обучить индивидуальную модель для переноса через среднюю матрицу
   и модель с обучаемой общей матрицей; получить отдельный индивидуальный референс.
5. Выбирать checkpoint по validation, затем выполнить итоговую оценку на test.
6. Сохранить результаты по участникам, фолдам и сидам, парные сравнения,
   конфигурации и происхождение всех артефактов.

## Разбиения и доступ к данным

Рабочая исходная схема — девять фолдов exp10: в каждом 21 обучающий участник,
3 валидационных и 3 тестовых. Для фолда `k` test — тройка `k`, validation —
тройка `(k + 1) % 9`, train — оставшиеся люди. Состав троек берётся из протокола
exp10 и сохраняется явно в будущем протоколе exp11. Первый фолд: validation —
`[1, 2, 14]`, test — `[11, 20, 22]`.

Разделение участников и разделение аудио — две отдельные проверки. Обучение
использует train-аудио обучающих людей без `3:4`; validation — `3:4` новых
валидационных людей; test — канонические test-окна новых тестовых людей.
Перекрывающиеся окна одного исходного интервала нельзя случайно распределять
по независимым аудиочастям.

Сохраняется авторская предобработка. Она использует неразмеченные данные записей,
в том числе целевых участников; параметры нормировки зависят от этих данных.
Поэтому бюджет **размеченной калибровки — 0 окон** не означает отсутствие доступа
к неразмеченным данным нового человека. Для ICA и нормировки нужно зафиксировать,
какие интервалы использованы при оценке их параметров. Более строгая обработка
без такого доступа будет отдельным протоколом, а не незаметной заменой авторской.

## Сравниваемые условия

| Условие | Обучение | Оценка | Назначение |
|---|---|---|---|
| `mean_unseen` | Индивидуальные матрицы только 21 обучающего человека | Среднее матриц только этих людей для новых validation/test участников | Основной baseline переноса |
| `shared_switch` | Личная матрица с вероятностью 0,9, общая — 0,1 | Всегда общая матрица для новых validation/test участников | Основная проверяемая модель |
| `own_seen` | Отдельное обучение с участием оцениваемых людей на разрешённом train-аудио | Собственная обученная матрица; test-аудио остаётся отложенным | Индивидуальный референс для знакомого человека |
| `shared_only` | Всегда общая матрица | Общая матрица | Дополнительный контроль по образцу exp10 |

Главное парное сравнение — `shared_switch` против `mean_unseen`: одинаковые
train/validation/test люди, окна, сиды и галерея. В `shared_switch` маршрут
выбирается для каждого примера; валидация и тест детерминированы. Матрицы новых
людей не обучаются и не входят в вычисление среднего.

`own_seen` отвечает на другую задачу: модель знакома с человеком. Его нельзя
получить, взяв необученный личный слот тестового человека из модели на 21 участнике.
Состав обучающих людей и правило validation для этого отдельного референса нужно
зафиксировать до запуска; это условие не выдаётся за перенос без обучения на человеке.
В итоговой таблице режим доступа к данным указывается рядом с каждой метрикой.

## Обучение, оценка и проверки

Исходные настройки для переноса из exp10: seed `42`, до 50 эпох, training batch
size `100`, learning rate `3e-4`, patience `7`, `p_personal=0.9`, авторский
CLIPLoss и AdamW. Перед основной серией настройки, набор сидов и список условий
фиксируются в отдельном протоколе exp11. Изменения после старта оформляются
отдельной серией с новым каталогом результатов.

Checkpoint выбирается по среднему Top-10 по валидационным людям, затем Top-1;
при полном равенстве сохраняется более ранняя эпоха. Test не используется
для early stopping, выбора вероятности маршрутизации, архитектуры или сида.

До полного обучения нужно проверить:

- Непересечение участников внутри фолда и аудиоинтервалов между соответствующими частями.
- Наличие всех MEG-ключей из CSV, корректность `wav_index` и соответствие аудиоокон таблицам.
- Границы MEG-окон с учётом `+150 мс`, формы, конечность значений и порядок каналов.
- Наличие clean-записей и параметров нормировки, одинаковую предобработку всех условий.
- Отсутствие обновлений весов на validation/test и использования матриц исключённых людей.
- Маршрутизацию новых людей через среднюю или общую матрицу согласно условию.
- Выбор checkpoint только по validation и одинаковый состав галереи в сравниваемых условиях.

Для первичной сверки канонических файлов уже есть команда из exp08/exp09.
Она выполняется из корня FQW в подготовленном окружении LISA:

```bash
python code/scripts/exp08_09_full_lisa/full_lisa.py check \
  --canon code/LISA/data/preprocessed
```

Это частичная проверка формата и канонических чисел, не полный аудит exp11.
Затем проводится короткий пилот в отдельном каталоге, проверяется весь путь
до сохранения результатов и запускается основная серия. Пилот подтверждает
исполнение; его test-метрики не используются для подбора основной конфигурации.

Метрики: Top-1, Top-10 и средний ранг. Сохраняются результаты по каждому человеку,
фолду и сиду, а также число кандидатов. Основная агрегация — сначала окна и
доступные сессии внутри человека, затем сиды, затем среднее по людям. Для основной
пары моделей сохраняются парные разности по людям; интервалы неопределённости
и статистический критерий задаются до итоговой оценки. Окна и фолды не считаются
независимыми заменами участникам.

## Артефакты и критерии завершения

Планируемые пути:

Данные, логи и checkpoint не добавляются в Git. Манифест содержит версии кода
и окружения, источники RAW/ICA, хеши входов и подготовленных файлов, настройки
предобработки, разбиения и фактические аргументы каждого запуска.

Эксперимент завершён, когда собственный комплект данных прошёл проверки,
выполнены все зафиксированные обучения и оценки, сохранена сводка по участникам
и условиям, а каждое итоговое число связано с конкретными данными и checkpoint.
Исторические результаты raw-серий exp08/exp09 и clean-серии exp10 остаются
контекстом; их нельзя подменять новыми числами или смешивать в основном сравнении.

После базовой серии можно отдельно проверять MoE/кластеризацию и роутинг,
перенос между сессиями, смену отложенной истории и расширение данных. Эти идеи
обсуждались на встрече, но пока не являются реализованными условиями exp11.
