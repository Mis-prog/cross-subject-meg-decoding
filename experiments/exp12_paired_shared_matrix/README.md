# Эксперимент 12 — сравнение средней и обучаемой общей матриц LISA

**Статус — план эксперимента.** Для этой серии запланировано 12 обучений: шесть фолдов, два варианта LISA и один сид `42`. В каждом фолде для обоих вариантов используются одни и те же 21 обучающий, 3 валидационных и 3 тестовых участника.

## Гипотеза

Общая матрица, которую LISA обучает совместно с личными матрицами, может повысить тестовый Top‑10 на новых участниках относительно арифметического среднего обученных личных матриц. Сравнение проводится на одинаковых участниках, звуковых фрагментах и настройках обучения.

## Задачи

1. Зафиксировать первые шесть разбиений `exp10`, сид `42` и одинаковый лимит эпох для обеих моделей.
2. Обучить два варианта на каждом фолде и отдельно выбрать их лучшие чекпойнты по валидации.
3. Оценить выбранные чекпойнты на тестовых участниках с одинаковым банком аудио и бюджетом размеченной калибровки 0 окон.
4. Сравнить Test Top‑10 попарно по людям. Для полной серии сохранить результаты всех 18 тестовых участников.

## Варианты subject layer

| Вариант | Обучение | Валидация и тест |
|---|---|---|
| `individual` — среднее личных матриц | Каждое окно МЭГ проходит через личную матрицу своего участника. | Используется арифметическое среднее 21 обученной личной матрицы текущего фолда. |
| `switch_p0p9` — обучаемая общая матрица | Для каждого окна независимо выбирается личная матрица с вероятностью 0,9 или общая с вероятностью 0,1. Общая матрица обучается на окнах, направленных через неё. | Для всех отложенных участников используется общая матрица из выбранного чекпойнта текущего фолда. |

При валидации `individual` среднее вычисляется из личных матриц текущей эпохи. В `switch_p0p9` общая матрица является отдельным параметром. Каждое обучающее окно проходит через одну выбранную матрицу. В обоих вариантах остальные обучаемые части LISA оптимизируются совместно со слоем матриц.

## Разбиение по участникам и аудио

Используются фолды `0–5` из [протокола exp10](../exp10_shared_matrix/protocol.json). Для фолда `k` тестом служит тройка `k`, валидацией — следующая тройка в исходном списке из девяти групп. Поэтому в фолде 5 валидация идёт на группе 6 (`4, 9, 13`). В обучение входят оставшиеся 21 человек. Внутри каждого фолда множества участников попарно не пересекаются.

| Фолд | Train | Validation | Test |
|---:|---|---|---|
| 0 | Остальные 21 | 1, 2, 14 | 11, 20, 22 |
| 1 | Остальные 21 | 16, 23, 26 | 1, 2, 14 |
| 2 | Остальные 21 | 10, 19, 24 | 16, 23, 26 |
| 3 | Остальные 21 | 12, 15, 17 | 10, 19, 24 |
| 4 | Остальные 21 | 3, 18, 27 | 12, 15, 17 |
| 5 | Остальные 21 | 4, 9, 13 | 3, 18, 27 |

| Выборка | Фрагменты | Банк аудиокандидатов |
|---|---|---:|
| Train | Канонические обучающие окна своих 21 участников, за вычетом фрагмента № 4 истории № 3 | — |
| Validation | Фрагмент № 4 истории № 3 у трёх валидационных участников | 108 |
| Test | Фрагменты № 5–11 истории № 3 у трёх тестовых участников | 1005 |

Авторское разбиение по аудио сохраняется во всех фолдах. Между фолдами меняется состав групп участников. Используются обе доступные сессии и авторская clean-предобработка с ICA из `exp10`. Бюджет размеченной калибровки составляет 0 окон. Авторская нормировка использует неразмеченные данные целевой записи.

## Обучение и оценка

- **Общие настройки.** Сид `42`, AdamW, learning rate `3e-4`, batch size `100`, patience `7` по протоколу `exp10`. Для обоих вариантов и всех фолдов используется один заранее выбранный лимит эпох.
- **Выбор чекпойнта.** После каждой эпохи вычисляется средний validation Top‑10 с равным весом участников. При равенстве выбирается больший Top‑1, при полном равенстве остаётся более ранняя эпоха. Выбор выполняется отдельно для каждой модели на каждом фолде.
- **Тест.** Выбранный чекпойнт ранжирует банк из 1005 аудиоокон для каждого тестового окна МЭГ. Веса модели фиксированы. Из рангов вычисляются Top‑10, Top‑1 и средний ранг по каждому участнику.
- **Основное сравнение.** Для каждого человека вычисляется `Test Top‑10(switch_p0p9) − Test Top‑10(individual)` в процентных пунктах. Сначала окна усредняются внутри участника по доступным сессиям, затем разницы усредняются по людям с равным весом. Один сид даёт сравнение для фиксированного запуска. Разброс по сидам остаётся открытым вопросом.

## Порядок ночного запуска

На двух GPU можно одновременно обучать `individual` и `switch_p0p9` одного фолда, по одной модели на GPU. На одной GPU оба варианта запускаются последовательно перед переходом к следующему фолду. Лимит эпох выбирается до основной серии по замеру длительности эпох на доступном сервере. Например, 15 эпох при 4 минутах на эпоху у более медленной модели дадут примерно 6 часов на шесть фолдов с двумя GPU, плюс загрузка данных и оценка.

Если к утру серия выполнена частично, в промежуточное сравнение входят фолды с результатами обоих вариантов. Вместе с метрикой указываются номера завершённых пар и фактическое число тестовых участников.

## Скрипты

Пути указаны относительно корня репозитория.

| Путь | Назначение |
|---|---|
| `experiments/exp12_paired_shared_matrix/scripts/check_coords.py` | Формы и конечность координат 208 датчиков, опциональная сверка с эталоном по SHA-256. |
| `experiments/exp12_paired_shared_matrix/scripts/check_data.py` | Наличие семи файлов, координаты, авторский состав аудиофрагментов и каноническая проверка таблиц, аудиоиндексов и ключей МЭГ. |
| `code/scripts/exp10_shared_matrix/run_experiment.py` | Формирование заданий, обучение и тестирование выбранных чекпойнтов. |
| `code/scripts/exp10_shared_matrix/subject_layer.py` | Среднее обученных личных матриц и маршрутизация 90/10. |
| `code/scripts/exp10_shared_matrix/run_server.sh` | Серверный запуск с журналом. |

Проверки запускаются из корня `FQW` в существующем окружении LISA. Для полного комплекта ожидаются `"problems": []`, 108 уникальных аудиоокон для validation и 1005 для test. При ошибках команда возвращает ненулевой код.

```bash
CANON=/абсолютный/путь/к/preprocessed
python experiments/exp12_paired_shared_matrix/scripts/check_data.py --canon "$CANON"
python experiments/exp12_paired_shared_matrix/scripts/check_coords.py --canon "$CANON"
```

Для проверки совпадения с доверенными координатами передайте любой команде `--reference-coords /путь/к/эталонному/coords`. Порядок датчиков подтверждается общим происхождением МЭГ и эталонной раскладки. История применения ICA проверяется по журналу или манифесту подготовки.

Оба варианта уже реализованы в `exp10`. Для этой серии используются явные задания `individual_f0_s42` и `switch_p0p9_f0_s42` через `train --task` и затем `eval --task`. Для остальных фолдов меняется номер после `f`. Выходы серии сохраняются в отдельном `--out outputs/exp12_paired_shared_matrix`. Парная сводка собирается из `eval/<task>/subjects.csv` по идентификатору участника и фолду. Штатный `summarize` в `exp10` рассчитан на три варианта.
