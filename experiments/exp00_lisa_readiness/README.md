## Гипотеза

Закреплённая версия LISA и локальное окружение позволяют выполнить прямой проход и несколько шагов обучения на синтетических массивах с конечными значениями loss и градиентов. Это техническое ожидание, а не гипотеза о качестве декодирования реальной речи.

## Задачи

1. Проверить версию upstream, зависимости и наличие входов, необходимых модели.
2. Выполнить синтетический CPU-прогон, проверить формы выходов, градиенты и отклонение неизвестного subject ID.
3. Проверить целевые тесты LISA и сохранить версии пакетов и результаты проверок.
4. Отдельно измерить скорость синтетических шагов на CPU и MPS; оценивать работоспособность устройства отдельно от качества модели.

## Путь от исходных данных до метрики

1. Два окружения: LISA и Montreal Forced Aligner (MFA).
2. Скачать исходные MEG-MASC и ICA-решения автора.
3. Получить временное выравнивание аудио и текста через MFA.
4. Подготовить wav2vec2-эмбеддинги, очищенные МЭГ, таблицы сегментов и массивы 100 Гц.
5. Запустить `lisa-train`; лучшая модель выбирается по validation loss.
6. Проверить `config.json`, `cli.txt`, `metrics.csv`, checkpoint и итоговые retrieval-результаты.

Затраты по README: около 300 ГБ на пике подготовки; около 18 ГБ для готового `data/preprocessed/`; около 180 ГБ при сохранении материалов для полного анализа. Это оценки авторов, не наши измерения. Полная матрица статьи не нужна для первого baseline.

Локальная машина: macOS ARM64. Здесь проверяем CPU. Обучающий CLI принимает CPU/CUDA, но не MPS. Наличие Apple GPU само по себе не даёт готового пути ускорения в этом CLI.

## Что происходит с новым испытуемым

`src/lisa/model/nn_modules.py`, класс `SubjectPlusLayer`: хранит отдельную обучаемую матрицу `A[s]` для каждого ID; матрицы исходно случайные. Модель по умолчанию имеет 27 ID (0–26). ID за пределами массива вызывает ошибку, автоматической подстановки общего слоя нет.

Если исключить человека из обучения, но оставить его ID в массиве, его матрица останется необученной. Это отдельный контроль случайной инициализации, а не удовлетворительный общий zero-shot baseline.

`src/lisa/cli/train_model.py`: стандартное разбиение выполняется по истории/фрагменту (`story_id`, `sound_id`), а не по субъекту. `N_SUBJECTS=27` зафиксирован в константах, загрузчик ожидает соответствующие имена файлов. CLI не предлагает готовых флагов LOSO, загрузки исходного checkpoint для few-shot адаптации или фильтрации отложенного человека.

Следствие: модель можно переиспользовать, но субъектное разбиение, инициализацию нового слоя и адаптацию нужно реализовать в отдельном экспериментальном коде.

## Методические ограничения, которые нужно учесть заранее

- Не называть результат на знакомых людях из статьи результатом на новых людях.
- Не использовать checkpoint, обученный на всех 27 людях, как исходную модель для честной оценки переноса на одного из них.
- Время калибровки считать по объединению реальных временных интервалов: окна перекрываются, сумма их длительностей завышает объём доступных данных.
- Для zero-calibration отдельно определить допустимый препроцессинг нового человека. ICA и нормализация, оценённые по полной записи, используют данные вне короткого бюджета. Для воспроизведения статьи это допустимый авторский протокол; для строгого исследования калибровки нужно явно описать другой режим или эту оговорку.
- Validation не должна содержать отложенного человека для выбора общей модели; финальный test не должен участвовать в выборе методов и параметров.

## Как повторить локальную проверку

Из корня проекта:

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python 'torch==2.6.0' -e 'code/LISA[dev]'
.venv/bin/python code/scripts/exp00_lisa_readiness/smoke_lisa.py --output experiments/exp00_lisa_readiness/results/lisa_cpu_smoke.json
```

Окружение через uv — наша локальная альтернатива Conda для проверки на macOS. Авторские скрипты MFA/подготовки вызывают Conda и не становятся совместимыми с `.venv` автоматически.

Smoke-прогон использует конфигурацию модели из CLI автора и комплектные координаты. Выполняет прямой проход, три шага оптимизации с CLIPLoss, расчёт retrieval среди 12 случайных кандидатов и проверку ошибки для неизвестного ID. Синтетические метрики не характеризуют научное качество.

Результаты и версии пакетов сохраняются в `experiments/exp00_lisa_readiness/results/`. Проверки на CPU не устанавливают воспроизводимость CUDA, подготовки данных или результатов статьи.

## Фактические результаты проверки

- Python 3.11.14, PyTorch 2.6.0, macOS ARM64, CPU; зависимости совместимы (`uv pip check`).
- Прямой проход: `[12, 208, 300]` → интерпретируемое представление `[12, 25, 300]` → эмбеддинги `[12, 768, 149]`.
- В модели 486 619 параметров; матрицы субъектов имеют форму `[27, 25, 270]` — 6 750 параметров на нового человека.
- Три шага оптимизации выполнены с конечными градиентами и loss. Время вычислительной части smoke-прогона: около 1.75 с; это не время обработки записи или обучения на MEG-MASC.
- Вызов неизвестного subject ID=27 действительно отклоняется.
- 41 тест пройден за 58.86 с, без пропусков; 14 предупреждений об устаревающих вызовах pyparsing в Matplotlib.
- Проверены пять файлов: `test_training_criteria.py`, `test_trainer_outputs.py`, `test_training_cli.py`, `test_training_data_validation.py`, `test_audio_reduction.py`. Полный набор тестов архитектурных вариантов не запускался.
- `lisa-train --help` работает, справка сохранена.

Артефакты: [smoke JSON](results/lisa_cpu_smoke.json), [JUnit](results/lisa_targeted_tests.xml), [версии пакетов](results/requirements-macos-cpu.txt), [CLI](results/lisa-train-help.txt).

## Дополнительная проверка Apple GPU

На Mac пользователя обнаружен Apple M4 с 24 ГиБ общей памяти. В ограниченной среде MPS определялся как недоступный; повторная проверка с разрешённым доступом к устройству подтвердила его работоспособность.

Официальный CLI отвергает `--device mps`, но прямой вызов модели через API на MPS прошёл forward, CLIP loss, backward и шаги AdamW без включения CPU fallback.

Измерение: два разогревочных и три измеряемых шага, случайные данные, CPU с четырьмя потоками.

| Устройство | Батч | Секунд на шаг |
|---|---:|---:|
| CPU | 12 | 0.0234 |
| MPS | 12 | 0.0272 |
| CPU | 100 | 0.6576 |
| MPS | 100 | 0.1430 |

При батче 100 MPS оказался примерно в 4.6 раза быстрее CPU в этом коротком тесте. Это не время полного обучения: измерение исключает загрузку данных, wav2vec2, validation/test, подготовку и сохранение результатов. Корректность/эквивалентность чисел CPU и MPS отдельно не установлена.

Полный обучающий CLI на MPS пока не адаптирован. Он загружает МЭГ-архив в словарь массивов целиком; для 24 ГиБ памяти нужно измерить весь рабочий набор, включая ОС, модель и аудиоэмбеддинги. Локальный пилот выглядит реализуемым; утверждение об обязательной NVIDIA GPU для него было слишком строгим.

Код проверки: `code/scripts/exp00_lisa_readiness/benchmark_lisa_device.py`. Результаты: [lisa_device_benchmark.json](results/lisa_device_benchmark.json).
