# Эксперимент 10 — обучаемая общая матрица испытуемого

Статус: clean-пилот на реальных MEG завершён 05.11.2026; основная серия обучается.
Протокол обновлён 05.11.2026: [protocol.json](protocol.json).
Основание — [встреча 19 октября, 34:00–39:23](../../docs/meetings/2026-10-19_semenkov_outcomes.md).

## Гипотеза

Если при обучении иногда заменять индивидуальную матрицу испытуемого общей,
общая матрица научится декодировать данные разных людей и улучшит перенос на
новых людей относительно среднего индивидуальных матриц и отдельной модели
только с общей матрицей. Это проверяемое ожидание, а не подтверждённый результат.

Первоначальная идея README связывала общую матрицу с MoE и запоминанием синтаксиса.
В текущем эксперименте маршрутизация задана вручную; разделение на «синтаксис»
и «личные особенности» не предполагается и не измеряется.

## Задачи

1. Обучить три условия на одинаковых разбиениях и сидах.
2. Выбирать checkpoint и вероятность маршрутизации по отдельным валидационным людям.
3. Оценить новых тестовых людей без дообучения, с теми же окнами и галереей exp09.
4. Сохранить метрики людей, фактические частоты путей и происхождение кода/данных.

## Схема и условия

На вход слоя поступает `x: (B, 270, T)`. Индивидуальные матрицы имеют форму
`A: (27, 25, 270)`, общая — `shared: (25, 270)`. Выход — `(B, 25, T)`.
Индексы людей внутри PyTorch начинаются с нуля; в таблицах — с единицы.

| Условие | Обучение | Валидация и тест |
|---|---|---|
| `individual` | Всегда личная матрица | Среднее матриц **только 21 обучающего человека** |
| `shared_only` | Всегда общая матрица | Общая матрица |
| `switch_p0p9` | Личная с вероятностью 0,9, общая с вероятностью 0,1 | Общая матрица |

Путь выбирается независимо для **каждого примера**, заново при каждом training
forward. Матрицы не складываются; масштабирование как в обычном dropout не
применяется. Во время `eval()` случайности маршрутизации нет. Попадание
валидационного или тестового человека в training forward вызывает ошибку.

Невостребованные матрицы в контролях заморожены. Остальные части LISA обучаются
совместно. Архитектура — 3D attention, unmixing, subject layer, временной фильтр,
два temporal blocks и single-conv голова; аудиопризнаки фиксированы. Loss —
авторский CLIPLoss с обучаемой температурой, оптимизатор AdamW, weight decay 0.
Пакеты с менее чем двумя уникальными аудиоокнами пропускаются и учитываются в логе.

Upstream LISA не изменяется. Адаптер локально создаёт ту же `single_conv` голову
с корректным `kernel_size`: в текущей учебной копии upstream есть `kernel_sie`.
HEAD LISA обязан совпадать с пином протокола; SHA-256 исходников сохраняются,
поэтому локальные изменения checkout видны в manifest.

## Разбиения и выбор модели

Сохранены девять тестовых троек exp09. Для фолда `k`:

- test — тройка `k`;
- validation — следующая тройка `(k+1) % 9`;
- train — оставшиеся 21 человек; обе доступные сессии.

Обучение использует только обучающих людей и train-окна, исключая историю 3,
звук 4. Валидация — история 3, звук 4 **только валидационных людей**, 108
кандидатов. Тест — канонические test-окна тестовых людей, галерея из 1005
аудиоокон. Обучающие, валидационные и тестовые люди не пересекаются внутри фолда.

Старт: сид 42, 50 эпох, batch size 100, learning rate `3e-4`, patience 7.
Checkpoint выбирается по среднему Top-10 по валидационным людям, затем Top-1;
при полном равенстве остаётся более ранняя эпоха. Test не вычисляется при обучении.

В протоколе стартовая сетка `p_personal=[0.9]`. Если расширить её **до запуска
новой серии**, `eval --all` выбирает p отдельно для каждого фолда и сида по
валидационным Top-10/Top-1; при равенстве — меньшую p. Расширение сетки или смена
протокола требует нового `--out`. `eval --task` предназначен для явной диагностики;
основную серию оценивайте через `eval --all`.

Бюджет размеченной калибровки — **0 окон**. Сохранена авторская нормировка каждой
записи по неразмеченным данным, включая целевые записи. Это не строгий перенос
без доступа к данным нового человека. Результаты exp09 — исторический ориентир:
там было 24 обучающих человека и другая стратегия валидации, прямое сравнение
процентов не изолирует эффект общей матрицы.

## Запуск на сервере

Нужны существующее Python 3.11-окружение LISA с CUDA PyTorch, pinned checkout
`code/LISA/` и данные **clean с авторскими ICA**, подготовленные из исходных RAW MEG-MASC
через `code/LISA/scripts/prepare_dataset.sh clean`. Сам training runner данные
не скачивает и не подготавливает.

05.11.2026 по просьбе пользователя до первого реального запуска exp10 подготовка
изменена с raw без ICA на авторский clean-пайплайн. Исторические результаты
exp08/exp09 получены без ICA; сравнение с ними дополнительно различается очисткой.

Используйте Python из серверного окружения LISA, например после `conda activate LISA`.

Передайте обновления репозитория на сервер, включая новый протокол. Если отправляете
только изменения, нужны `code/scripts/exp10_shared_matrix/`,
`experiments/exp10_shared_matrix/protocol.json` и существующий пакет
`code/scripts/exp08_09_full_lisa/`. `.env` для этого эксперимента не требуется.

Все следующие команды выполняются **на сервере из корня FQW**. В примерах
`/data/preprocessed` замените путём к каноническим данным. Для выбора GPU используйте
`CUDA_VISIBLE_DEVICES`; внутри процесса устройство остаётся `cuda`.

```bash
python -c 'import torch, lisa; print(torch.__version__, torch.cuda.is_available())'
python code/scripts/exp10_shared_matrix/run_experiment.py tasks --fold 0

# Пилот: три модели первого фолда. Запускайте внутри tmux.
CUDA_VISIBLE_DEVICES=0 PYTHON=python bash code/scripts/exp10_shared_matrix/run_server.sh \
  train --all --fold 0 --canon /data/preprocessed --out outputs/exp10_pilot

# После обучения: тест трёх условий, затем сводка первого фолда.
CUDA_VISIBLE_DEVICES=0 PYTHON=python bash code/scripts/exp10_shared_matrix/run_server.sh \
  eval --all --fold 0 --canon /data/preprocessed --out outputs/exp10_pilot
python code/scripts/exp10_shared_matrix/run_experiment.py summarize --out outputs/exp10_pilot
```

Первый фолд: train — 21 человек; validation — `[1, 2, 14]`; test — `[11, 20, 22]`.
Пилот означает проверку исполнения; не меняйте метод по его тестовым метрикам.
Для проверки на одной эпохе задайте `--nepoch 1` и **отдельный** `--out`, затем
запустите полное обучение с исходным протоколом в новом каталоге.

```bash
# Полная серия: 9 фолдов × 3 условия × 1 сид = 27 обучений последовательно.
CUDA_VISIBLE_DEVICES=0 PYTHON=python bash code/scripts/exp10_shared_matrix/run_server.sh \
  train --all --canon /data/preprocessed --out outputs/exp10_full
CUDA_VISIBLE_DEVICES=0 PYTHON=python bash code/scripts/exp10_shared_matrix/run_server.sh \
  eval --all --canon /data/preprocessed --out outputs/exp10_full
python code/scripts/exp10_shared_matrix/run_experiment.py summarize --out outputs/exp10_full
```

Несколько серверов/GPU: назначайте разные `--fold k` отдельным процессам. Каждый
процесс использует одну GPU. На одной машине одинаковые задания блокируются;
на разных серверах распределение фолдов задавайте вручную. Для общей сводки соберите
каталоги `runs/<task>/` и `eval/<task>/` всех фолдов в один `--out`. Сводка не требует
MEG/GPU. Для тестирования используйте тот же сервер и канонические данные, что при
обучении: происхождение проверяется до открытия тестовых массивов.

`--workers N` управляет DataLoader; по умолчанию 0. Каждый worker кеширует свои
записи, поэтому увеличение N повышает расход RAM. `--batch-size` и `--eval-batch-size`
помогают подобрать расход GPU-памяти. Изменение training batch size — изменение
фактических настроек серии, сохраняемое в manifest; сравнивайте одинаковые настройки.

## Артефакты и повторный запуск

В `--out` сохраняются:

- `runs/<task>/`: протокол, config, manifest, `metrics.csv`, `best.pt`,
  лучшие валидационные ранги и метрики людей, `done.json`;
- `eval/<task>/`: ранги всех тестовых окон, метрики людей, SHA-256 checkpoint;
- `summary/`: метрики людей с усреднением по сидам, средние и 95% t-интервалы,
  парные Wilcoxon-сравнения Top-10 с поправкой Холма, полнота выполненных фолдов;
- `logs/`: журналы серверного launcher по умолчанию; путь можно задать через `EXP10_LOG_DIR`.

Повторный train пропускает завершённую задачу только при совпадении происхождения
и настроек. Прерванный run автоматически не возобновляется: checkpoint содержит
оптимизатор для диагностики, но точный resume не реализован. Для перезапуска используйте
новый `--out` либо сначала вручную разберите незавершённый каталог.

Малые исходники, таблицы и координаты проверяются SHA-256. Большие MEG/audio
массивы фиксируются путём, размером и mtime; это **не** побайтовая проверка данных.
Версии Python/PyTorch/NumPy/pandas, CUDA и название GPU записываются в manifest.
Сводка отклоняет сравнение условий с разными настройками обучения или входными файлами.
Метрики частичной серии помечаются как неполные; научный результат требует реальных запусков.

Синтетическая проверка обучает три маленькие модели на CPU одну эпоху, загружает
