# Эксперимент 07 — калибровка LISA без дообучения весов

[Каталог](../README.md) · [Код](../../code/scripts/exp07_frozen_calibration/README.md) · [Протокол](protocol.json)

**Статус после встречи 05.10.2026:** скрипты и протокол подготовлены;
подтверждённых результатов серии в репозитории нет. Ближайший согласованный
порядок — авторское воспроизведение → перенос между сессиями → простой baseline
со средней Wₛ для новых людей → поиск похожих участников.
См. [итоги встречи](../../docs/meetings/2026-10-05_semenkov_outcomes.md).
Перечень методов ниже сохраняется как подготовленный план; встреча не означает
утверждение запуска всех восьми методов. `gain_mean_ws` остаётся полезным
диагностическим контролем, но не подменяет согласованный простой mean-Wₛ baseline.
После смены upstream или протокола требуется проверить совместимость скриптов;
текущие JSON-настройки и результаты exp06 этой записью не изменяются.

Этот запуск использует готовые `shared` checkpoint из exp06. Он проверяет, можно ли
улучшить перенос на нового человека, сохранив обучаемые параметры сети неизменными.
Выбор готовой матрицы, оценка статистик и аналитическое выравнивание всё равно
являются адаптацией по калибровочным данным; градиентного дообучения здесь нет.

## Гипотеза

Адаптация масштаба, выбор или ансамбль готовых матриц, перенастройка статистик BatchNorm либо аналитическое выравнивание способны улучшить mean_ws при фиксированных обучаемых параметрах LISA. Сравнение проводится при бюджетах 0/30/120 секунд и одинаковых разрешённых данных; это гипотеза подготовленной серии, подтверждённых результатов которой пока нет.

## Задачи

1. Проверить checkpoint exp06, подготовленные массивы, хеши, upstream и отсутствие отложенного участника среди источников.
2. Выбрать настройки масштаба и BatchNorm на dev-участниках 1–3; зафиксировать их до итоговой оценки.
3. Сравнить предусмотренные протоколом методы на участниках 4–27 по трём сидам и одинаковым вложенным калибровочным блокам.
4. Проверить неизменность обучаемых параметров, отсутствие доступа к test при выборе настроек и целостность результатов; агрегировать качество по людям.

## Что сравниваем

| Метод в результатах | Что меняется | Нужен известный звук при калибровке |
|---|---|---|
| `mean_ws` | Средняя матрица обучающих людей; контроль из exp06 | Нет |
| `gain_mean_ws` | Масштаб средней матрицы, правило выбрано на dev | Нет |
| `ensemble` | Усреднение оценок сходства с аудио при готовых матрицах источников | Нет |
| `select_ws` | Выбор одной готовой матрицы по калибровочному соответствию МЭГ–аудио | Да |
| `adabn` | Только статистики BatchNorm; обучаемые коэффициенты неизменны | Нет |
| `align_scalar` | Общий коэффициент и смещение в пространстве 25 ветвей | Да |
| `align_diagonal` | Отдельный коэффициент и смещение для каждой ветви | Да |
| `align_procrustes` | Ортогональное выравнивание 25 ветвей со смещением | Да |

Последние три метода стоят после subject-слоя, до временной фильтрации. Их опорный
сигнал — усреднённые реакции обучающих людей на тот же звуковой фрагмент. Для каждого
фолда используется именно его checkpoint и его список `fit_subjects`: отложенный
человек не попадает в шаблон или банк матриц. Это проверка идеи общего стимула;
результат для незнакомой записи без опорных реакций из неё автоматически не следует.

Бюджеты: **0, 30 и 120 секунд**. На ненулевой бюджет — три повторения. Для каждого
повторения 30 секунд вложены в выбранный блок 120 секунд; методы получают одинаковые
окна и нормировку. Блок не пересекает границу аудиофрагмента. В имеющемся разбиении
непрерывный train-фрагмент не длиннее 177 секунд, поэтому 300 секунд нельзя честно
назвать одним непрерывным фрагментом. Бюджет 120 секунд доступен в `easy_money`;
это ограничивает разнообразие калибровочного стимула.

В 0 секунд оцениваются `mean_ws`, `gain_mean_ws`, `ensemble` с population-нормировкой.
В 30/120 секунд нормировка нового человека оценивается только по окнам бюджета.
Таким образом, ненулевой бюджет у baseline тоже означает калибровку нормировки.

## Порядок запуска

Сначала проверка файлов, формы массивов, метаданных и checkpoint:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage check
```

План без запуска и без чтения массивов:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage all --dry-run
```

Подбор настроек по validation у людей 1–3, seed 0. Здесь запускаются три задачи,
затем фиксируется общий выбор в `tuning.json`:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage tune --workers 1
```

Проверка всей цепочки на одном оцениваемом человеке и одном сиде, уже с выбранными
на dev настройками. Это полноценный расчёт одного фолда, а не оценка финального
качества по всей выборке:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage evaluate --holdouts 4 --seeds 0 --workers 1
```

После проверки запускай остальных; уже выполненный фолд пройдёт проверку сохранённого
результата и будет пропущен самим вычислительным скриптом:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage evaluate --workers 1
```

Или весь порядок одной командой:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage all --workers 1
```

Для долгого запуска используй устойчивую к разрыву SSH сессию, например `tmux`.
В полной серии **75 вычислительных задач**: 3 dev + 24 человека × 3 сида; проверка,
выбор настроек и сводка выполняются отдельно. Точное время и пик памяти для этой
серии ещё не измерены. Начни с одного процесса. При достаточном запасе GPU-памяти
можно использовать `--workers 2`; каждый процесс держит собственную модель.

Пути можно переопределить без изменения кода:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/run_frozen_loso.py --stage all --workers 1 \
  --data-dir /path/to/loso \
  --runs-dir /path/to/loso_runs \
  --output-dir /path/to/frozen_loso \
  --coords-dir /path/to/LISA/data/preprocessed
```

`--coords-dir` указывает на каталог, **содержащий** `coords/`, а не на сам `coords/`.
Другие параметры: `--batch-size 64`, `--device cuda`. При нехватке GPU-памяти сначала
оставь `--workers 1`, затем уменьши `--batch-size`, например до 16. `--device cpu`
поддержан для диагностики, но полную серию на CPU запускать необязательно.

При прерывании повтори ту же команду. Готовность определяется проверяемым receipt и
отпечатком входов, а не наличием файла с результатом. Если протокол, код или входы
изменились, используй **новый `--output-dir`**; не удаляй проверки и не перемешивай
результаты разных настроек в одной сводке. Ошибка задачи останавливает зависимые
этапы; Ctrl+C останавливает дочерние процессы.

Сводка также проверяет хеш протокола и одинаковый хеш выбранных dev-настроек во всех
фолдах, а также целостность самих receipts. Если `tuning.json` сохранён рядом,
его содержимое сверяется с этим хешем.

## Где смотреть результаты

По умолчанию всё пишется в `experiments/exp08_09_full_lisa/results/frozen_loso/`:

- `logs/` — отдельный журнал на задачу, дополняемый при повторном запуске.
- `manifest.json` — проверенные входы, их хеши, версия кода и окружение.
- `tune/h01_s0.json` … `h03_s0.json` — результаты подбора на dev.
- `tuning.json` — зафиксированные настройки перед оценкой.
- `evaluate/h04_s0.json` … `h27_s2.json` — результаты каждого фолда и provenance.
- `records.csv` — результаты методов по человеку, сиду, бюджету и повтору.
- `per_subject.csv` — сначала усреднённые повторы, затем сиды внутри человека.
- `summary.csv`, `summary.md`, `summary.json` — сводка и полнота серии.
- `paired_vs_gain.csv` — парные отличия от `gain_mean_ws` при том же бюджете.

Внутри evaluation receipts сохраняются также `calibrations` с точными окнами,
нормировкой, выбранными матрицами, статистиками BatchNorm и аналитическими картами,
а `audit` подтверждает неизменность параметров сети. Поле каждой строки
`by_story_same_gallery` содержит отдельные показатели для запросов `lw1` и
`easy_money` против того же полного банка кандидатов. Это срез по историям,
не проверка на истории, которой модель никогда не видела.

В одном полном evaluation-receipt **51 строка**: три метода при 0 секунд и восемь
методов × два бюджета × три повторения. Отсутствующие фолды явно помечаются;
незаконченный набор сидов человека не попадает в сводные оценки. Для выборочного
прогона сводка явно говорит, что это подмножество основной серии.

Сводку можно пересчитать отдельно:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/summarize_frozen_loso.py
```

После одного пробного фолда, чтобы увидеть именно его описательные результаты:

```bash
.venv/bin/python code/scripts/exp07_frozen_calibration/summarize_frozen_loso.py --holdouts 4 --seeds 0
```

Основной показатель — Top-10. Также сохраняются Top-1, средний ранг, loss и время.
Метрики Top-k в CSV хранятся как доли 0–1, в `summary.md` — как проценты.
Для сравнений сначала усредняются повторы и сиды внутри человека; затем считаются
парные разницы по людям, 95% bootstrap-интервалы, доля улучшившихся людей,
медиана и качество худшей четверти. **72 фолда × сида — это 24 независимых человека**,
а не 72 независимых наблюдения.

## Как интерпретировать серию

1. Сначала сравни `gain_mean_ws` с `mean_ws`: это контроль уже обнаруженного провала
   масштаба средней матрицы. Основной baseline для остальных методов — `gain_mean_ws`.
2. `ensemble` против `select_ws` показывает, полезнее ли сохранять разнообразие
   готовых матриц или выбрать одну по короткой записи нового человека.
3. `adabn` проверяет пользу статистической калибровки без знания аудио.
4. Лесенка `align_scalar` → `align_diagonal` → `align_procrustes` показывает,
   достаточно ли поправить общий масштаб, масштабы отдельных ветвей или нужно
   менять их взаимную ориентацию. Усложнение метода само по себе не доказывает пользу.

Настройки выбираются только по validation dev-людей, до финальной оценки. Test из
exp06 уже анализировался, поэтому эта серия **исследовательская**, а не независимая
подтверждающая проверка. Для подтверждения потребуется новая сессия или история.
Проверка размеров головы и геометрической регистрации в эту серию не включена.

Сравнение с историческими `ft_Ws` из exp06 носит описательный характер: там отрезки
выбирались из объединённого train-пула и могли пересекать границы фрагментов, здесь
используется строгая непрерывность. Для точного парного сравнения калибраторов с
дообучением их надо повторить на тех же новых блоках.

Бюджет 30/120 секунд относится к калибровке **после готовой ICA-обработки**. Имеющиеся
ICA-решения получены по более длинной записи. Поэтому нельзя утверждать, что весь
путь от сырых сигналов до результата обходится только этими 30/120 секундами.
Доверительные интервалы описательные; поправка на множественные сравнения здесь
не выполняется, и они не заменяют заранее заявленную подтверждающую проверку.

## Локальная проверка реализации

Проверены численные преобразования, неизменность нейровесов, положение внешней
карты перед временными фильтрами, статистики AdaBN, разделение калибровки и оценки,
согласование CLI, возобновление и целостность результатов. Вся цепочка
`tune → choose → evaluate → summary` выполнена на синтетическом наборе с небольшой
тестовой сетью: **37 тестов и 12 дополнительных проверок внутри тестов прошли**.

```bash
.venv/bin/python -m pytest tests/test_frozen_loso_math.py \
  tests/test_frozen_loso_adapter.py tests/test_frozen_loso_runner.py \
  tests/test_frozen_loso_pipeline.py -q
```

Полноценный запуск LISA на настоящих массивах здесь не выполнен: полных массивов
LOSO на ноутбуке нет, а установленный SciPy имеет ошибку загрузки библиотеки
на текущей macOS. Зависимости проекта не менялись. Серверный `--stage check`
проверяет точные хеши exp06 и выполняет короткий forward настоящего checkpoint
перед основной очередью.
