# Контроль exp08: одинаковые 22 человека в обоих направлениях

[Каталог](../README.md) · [Код](../../code/scripts/exp08_matched22/README.md) · [Протокол](protocol.json) · [Результаты](results/)

Протокол: [matched22_protocol.json](protocol.json). Подготовлен 18.10.2026,
проведён 18–19.10.2026 на Vast.ai (RTX A4000 16 ГБ). Исходные результаты остаются в `outputs/full_raw`.

## Гипотеза

Наблюдаемая асимметрия падения Top-10 между направлениями ses-0 → ses-1 и ses-1 → ses-0 не целиком объясняется различным составом обучающих участников исходной серии. Проверка — сравнить парные падения own_cross − own_same после уравнивания обеих групп до тех же 22 людей. Это проверяемое предположение; статистический вывод приведён отдельно ниже.

## Задачи

1. Зафиксировать одних 22 участников, одинаковые аудиоокна, предобработку raw без ICA и условия обучения для A/B.
2. Перед переиспользованием старых B-моделей проверить конфигурации, состав доноров и совпадение оценок на текущих данных.
3. Обучить только новые A-модели по сидам 42/43/44 и оценить те же условия, что у B.
4. Сопоставить падения по тем же людям после усреднения сидов, применить согласованную поправку Холма и сохранить аудит входов и оценок.

## Итоги (19.10.2026)

**Вывод.** Смена сессии значимо снижает качество в обоих направлениях. Асимметрия
«A теряет меньше, чем B» сохраняется в той же величине (14,3 п.п. против 14,6 п.п. в
исходной серии), но, как и там, не подтверждается после поправки Холма (p = 0,13).
Значит, неравный состав людей (27 против 22) асимметрию не объяснял: убрали это
различие, а картина не изменилась.

по людям ([summary.csv](results/summary.csv)):

|---|---:|---:|---:|
| Своя матрица, исходная сессия (`own_same`) | 65,8 ± 8,0 | 67,2 ± 7,0 | 67,3 |
| Своя матрица, другая сессия (`own_cross`) | 46,4 ± 9,0 | 33,6 ± 10,2 | 48,3 |

| Чужая, среднее по 21 донору (`other_cross`) | 11,4 ± 2,2 | 9,1 ± 2,7 | 12,7 |

Top-1: A 35,5 → 20,5%, B 36,7 → 14,1%. Случайный уровень Top-10 при 1005 кандидатах ≈ 1%.

Парные сравнения по Top-10, тест Уилкоксона по 22 людям, Холм по 21 проверке

Без поправки p главного сравнения 0,042; по среднему рангу (вспомогательный показатель,
без поправки) 0,009. Это направление, а не доказанный эффект: ДИ по t почти касается нуля,
а у 6 человек асимметрия обратная и крупная (5, 6, 17, 23, 24, 26: от −13 до −41 п.п.).
По людям ([per_subject.csv](results/per_subject.csv)) у 2, 4, 8, 22 падение
в B превышает 60 п.п. при умеренном в A; разброс между людьми больше, чем сама разница.

Что эксперимент **не** разделяет: сессия 1 всегда вторая, поэтому смена визита,
повторное прослушивание и привыкание к процедуре по-прежнему связаны.

## Зачем

В исходном A (ses-0 → ses-1) обучались 27 людей, в B (ses-1 → ses-0) — 22.
Теперь оба направления используют одних и тех же людей: все, кроме 3, 12, 16, 20, 21.
Новые обучения: только A, сиды 42/43/44. Результаты B переиспользуются после проверки.
При оценке своей матрицы используются только эти 22 человека; средняя и чужие
матрицы берутся из остальных **21 обученного слота**, собственный слот исключён.

Главное сравнение — разница `(own_cross − own_same)` между направлениями по Top-10.
Сначала усредняются сиды внутри человека, затем считаются парные различия по 22 людям.
Сохраняется семейство сравнений и поправка Холма из `summarize_full.py`; средний ранг
остаётся вспомогательным показателем без поправки. Потолок из модели на 27 людях
в эту сводку не добавляется. Смена визита и повторное прослушивание по-прежнему
связаны: этот контроль не позволяет установить причинный эффект знакомства со стимулом.

## Данные и проверки до обучения

Пользователь подтвердил: предыдущая серия `full_raw` использовала **raw без ICA**,
источник — NEMAR nm000229. Для контроля восстанавливается та же версия зеркала
`v1.0.1` из существующего `download_nemar.py`, затем прежнее преобразование событий
`nemar_events_to_osf.py` и пайплайн авторов `prepare_dataset.sh raw`.
Не заменять raw на clean и не обновлять checkout LISA при этом контрольном запуске.

`run_matched22.py check` проверяет:

- Канонические размеры данных и разделение обучающих/тестовых звуков.
- Одинаковый состав людей и точные идентификаторы аудиоокон каждого человека в обеих
  сессиях, отдельно для train (включая validation) и test; дубликаты запрещены.
- Старые B-конфиги и текущие настройки обучения; размер обучающего батча остаётся 100.
- Полноту старых B-оценок: все окна, люди, сессии и ровно 21 допустимый донор.
- На текущих массивах заново оценивает **сохранённые B-модели** на обеих сессиях
  (без обучения) и сравнивает ранги со старыми. Требуется ≥93% точных совпадений,
  ≥99,9% рангов с разницей не более 2, расхождение Top-10 ≤0,2 п.п. Исходно порог
  точных совпадений был 95% (допуск `full_lisa.py`); снижен 19.10.2026, см. ниже.

**Решение 19.10.2026: порог точных совпадений снижен с 95% до 93%.** На RTX A4000
(Vast.ai) сохранённые B-модели дали:

| B / условие | Точно | ≤2 | Макс. разница | Top-10 старый → новый |
|---|---|---|---|---|
| s42 own_same | 98,10% | 99,986% | 4 | 67,87 → 67,86% |
| s42 own_cross | 94,79% | 99,941% | 4 | 33,88 → 33,88% |
| s43 own_same | 98,32% | 99,991% | 3 | 67,26 → 67,25% |
| s43 own_cross | 95,21% | 99,946% | 6 | 33,64 → 33,64% |
| s44 own_same | 97,98% | 99,991% | 4 | 66,49 → 66,48% |
| s44 own_cross | 94,21% | 99,950% | 3 | 33,30 → 33,30% |

Не проходил только порог 95% в двух own_cross. Top-10 и медианный ранг совпадают,
остальные допуски выполнены с запасом. Расхождение трактуется как численный шум другой
GPU: в own_cross ранги средние (медиана 38), оценки плотнее, и малые сдвиги чаще
переставляют соседей. Старые B не переобучались.

Эта проверка подтверждает численную совместимость для оценки. Она не является
доказательством побитового совпадения старых train-массивов: их хеши не сохранены.
Текущие входы, исходники и B-артефакты хешируются, версии библиотек записываются.
Повторный запуск с изменёнными входами останавливается и требует отдельную папку вывода.
Если B не воспроизводится, обучение A не начинается: сначала восстановить старый
пайплайн либо отдельно запланировать обучение обоих направлений на новых данных.

## Сервер и время

Для GPU с 16 ГБ VRAM по умолчанию запускается **одна модель за раз**, батч оценки — 32.
Совместимость конкретной GPU/драйвера с окружением CUDA проверяет setup; фактический
расход VRAM проверяется первым запуском. Не уменьшать обучающий батч автоматически:
это изменит задачу contrastive learning относительно B.

Обработанные массивы занимают около 18 ГБ; ориентир для системной RAM — от 32 ГБ,
предпочтительно 64 ГБ. Предобработка по умолчанию использует 4 процесса; если памяти
мало, задайте `PREP_JOBS=1`. Для диска с запасом под загрузку, обработку и окружения
предусмотрите около 300 ГБ. Это резерв, не замер максимума именно raw-пайплайна.

В старой серии A было по 18 эпох, B — 19–21. Поэтому ориентир новой серии — примерно
60 эпох суммарно, но ранняя остановка может отличаться, предел — 50 эпох на модель.
Журналы длительности предыдущей полной серии локально не сохранились. Число часов
нельзя определить по одному объёму VRAM: при 2 мин/эпоху 60 эпох займут около 2 ч,
при 5 мин/эпоху — около 5 ч. Скачивание, MFA, предобработка, проверка B и оценка A —
дополнительное время. Это условные расчёты, не измеренная скорость.

Начните с `pilot`: он полностью обучит и оценит seed 42, сохранит длительность в
`outputs/full_matched22/timings.jsonl`, а обычный запуск пропустит завершённый сид.
Первичная проверка B не входит в этот таймер; времена отдельных обучения и оценки
видны в `logs/matched22/series.log`.

## Запуск с нуля на Vast.ai

На ноутбуке, из корня FQW, после получения SSH-адреса:

```bash
bash code/scripts/exp08_matched22/vast/push_matched22.sh PORT HOST
```

Загружаются код и только нужные B-веса/оценки. Подготовленных массивов на ноутбуке нет.
Скрипт использует прежний `push.sh`, включая существующий `.env`; его содержимое не печатается.

На сервере:

```bash
cd /workspace/FQW
bash code/scripts/exp08_matched22/vast/matched22.sh setup
# Если tmux уже есть, можно открыть сессию и до setup.
tmux new -s matched22
bash code/scripts/exp08_matched22/vast/matched22.sh data
bash code/scripts/exp08_matched22/vast/matched22.sh check
bash code/scripts/exp08_matched22/vast/matched22.sh pilot
bash code/scripts/exp08_matched22/vast/matched22.sh run
```

`pilot` необязателен: `run` сразу выполнит все три сида последовательно.
После прерывания `run` пропускает полностью завершённые обучения/оценки. Незавершённое
обучение начинается заново; это не восстановление оптимизатора с последней эпохи.
Не запускать `data` повторно во время обучения. Чтобы покинуть tmux без остановки:
Ctrl+B, затем D.

Перед основной серией можно выполнить быстрые проверки:

```bash
conda activate LISA
python -m pytest tests/test_matched22.py -q
```

Результаты: `experiments/exp08_matched22/results/{summary,comparisons,per_subject}.csv`.
Финальная сводка запрещена, пока нет всех трёх сидов A и B с полными условиями.
Настройки новых A-моделей ещё раз сверяются с B. Чтобы пересчитать готовую сводку:

```bash
bash code/scripts/exp08_matched22/vast/matched22.sh summary
```

С ноутбука, до удаления сервера:

```bash
bash code/scripts/exp08_matched22/vast/pull_matched22.sh PORT HOST
```

Этот скрипт дополнительно сохраняет журнал времени и контрольные хеши. Подготовленные
массивы автоматически не скачиваются; для следующей серии стоит отдельно сохранить
`code/LISA/data/preprocessed/` вместе с протоколом и журналами подготовки.

## Локальная проверка

Пять тестов проверяют исключение людей из обучения и оценки, состав среднего и
доноров, несовпадение аудиоокон при равном количестве строк, неполные оценки,
неверные ранги и защиту путей старых артефактов. Проверены синтаксис скриптов и
соответствие текущих параметров CLI реальному конфигу B. Полный GPU-запуск и
численная проверка B требуют серверных массивов. Локальный SciPy не загружается
из-за ошибки бинарной библиотеки; итоговую статистику следует считать в серверном
окружении LISA, зависимости ноутбука не менялись.
