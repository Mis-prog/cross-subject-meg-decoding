## Гипотеза

При совпадении версии LISA, конфигурации, подготовки данных и retrieval-протокола можно воспроизвести качество авторского эталонного запуска на знакомых участниках. Сравнивать качество следует только после проверки совпадения этих условий.

## Задачи

1. Зафиксировать версию upstream и эталонную конфигурацию; сопоставить условия с авторским запуском.
2. Получить готовые входы или подготовить данные авторским пайплайном, проверить датчики, размеры массивов и разбиения.
3. Выполнить проверку батча и одну эпоху, измерить память и время, затем запустить полный baseline.
4. Выбрать checkpoint по validation и оценить test на фиксированном банке кандидатов; сохранить конфигурацию и метрики.

## Два возможных пути к данным

**Быстрый путь:** получить у автора готовое `data/preprocessed/` вместе с описанием подготовки и исходной конфигурацией. По README полный комплект занимает около 18 ГБ. Проверить содержимое и соответствие commit до обучения.

**Самостоятельная подготовка:** следовать авторскому README: окружения LISA/MFAligner → скачивание исходных записей и ICA → MFA → подготовка clean. На пике требуется около 300 ГБ; локально эти этапы ещё не проверены. Скрипты ожидают Conda, локальная `.venv` её не заменяет.

Обязательные входы для стандартного обучения:

- `audio/extract_features_train4.npy`, `audio/extract_features_test4.npy`;
- `dataframe/df_train27.csv`, `dataframe/df_test27.csv`;
- `meg/meg27_sr100.npz`;
- комплектные файлы `coords/`.

Проверить дополнительные требования финальных визуализаций к очищенным FIF: наличие только массивов для обучения не гарантирует выполнение всего анализа.

## Порядок запуска

1. Проверить наличие файлов, совпадение числа/порядка датчиков, допустимость индексов аудио, формы массивов, непустые fit/validation/test.
2. Проверить загрузку одного батча и finite loss на выбранном устройстве.
3. Запустить одну эпоху на подготовленных стандартных входах для измерения ресурсов.
4. После успешного прогона запустить один полный baseline seed 42.

Из корня репозитория LISA в активированном окружении, после подготовки всех входов:

```bash
lisa-train --run-group fqw-baseline-check-seed42 --device cuda --nepoch 1
lisa-train --run-group fqw-baseline-seed42 --device cuda --torch-deterministic
```

Это проверенные по исходникам варианты CLI, но на данных здесь они ещё не исполнялись. Второй запуск использует defaults модели; для точного воспроизведения конкретного результата сверить их с авторскими `config.json` и `cli.txt`. Первая команда обрабатывает стандартный датасет одну эпоху, а не одного испытуемого. Готового флага малого субъектного поднабора нет.

## Оценка

- Зафиксировать точную модель, очистку, аудиоэмбеддинги, границы фрагментов, банк кандидатов и конфигурацию.
- Top-1/Top-10 рассчитывать по полному фиксированному банку кандидатов.
- Сохранять validation loss, итоговые test-метрики, время эпохи, пиковую RAM/VRAM, использованное устройство.
- Результат модели на знакомых людях не считать LOSO или гарантированным «потолком».
- Результаты разных работ не сравнивать напрямую без выравнивания условий подготовки и retrieval.
